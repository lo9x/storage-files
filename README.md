# Storage Files — облачное хранилище

Учебный проект по производственной практике: веб-сервис для загрузки, хранения,
организации и обмена файлами.

**Стек:** ASP.NET Core 10 (MVC), Entity Framework Core 10, SQLite, Bootstrap 5, cookie-аутентификация.

> Сейчас готовы **недели 1–2** из плана на 4 недели: аккаунты, личное пространство,
> файловый менеджер, поиск/сортировка, корзина и лимит хранения.
> Общий доступ по ссылкам и админ-панель — в неделях 3–4 (см. [docs/PLAN.md](docs/PLAN.md)).

## Что уже работает

- Регистрация, вход и выход; пароли хранятся в виде хешей (`PasswordHasher`).
- Роли `User` и `Admin`; при первом запуске создаётся администратор.
- Личное пространство: каждый пользователь видит только свои папки и файлы.
- Папки: создание, переименование, перемещение, удаление в корзину, навигация по вложенности.
- Файлы: загрузка (до 20 файлов за раз, до 100 МБ каждый), скачивание, переименование,
  перемещение, удаление в корзину.
- Поиск по имени в текущей папке и сортировка по имени, размеру и дате.
- Корзина: восстановление и окончательное удаление файлов и папок, очистка корзины.
- Лимит хранения: отображение занятого места и запрет загрузки сверх лимита.
- Проверка ввода, защита от подделки форм (anti-forgery), адаптивный интерфейс.

## Быстрый запуск

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download).

```bash
dotnet restore
dotnet run --project src/StorageFiles.Web --launch-profile http
```

Откройте <http://localhost:5080>.

При первом запуске EF Core применит миграции и создаст:

- базу — `src/StorageFiles.Web/App_Data/storagefiles.db`;
- файлы пользователей — `src/StorageFiles.Web/App_Data/storage/`.

**Администратор по умолчанию:**

| Email | Пароль |
| --- | --- |
| `admin@storage.local` | `Admin123!` |

Данные для входа задаются в `src/StorageFiles.Web/appsettings.json` (секция `Seed`).
Перед публикацией пароль нужно изменить.

### Полезные команды

```bash
# сборка
dotnet build

# применить миграции вручную (обычно не требуется — приложение делает это само)
dotnet ef database update --project src/StorageFiles.Web --startup-project src/StorageFiles.Web

# новая миграция после изменения моделей
dotnet ef migrations add <Name> --project src/StorageFiles.Web --startup-project src/StorageFiles.Web --output-dir Data/Migrations
```

## Как устроено хранение

1. При загрузке файл сохраняется на диск под случайным именем (`guid + расширение`)
   в каталоге пользователя: `App_Data/storage/{userId}/`.
2. В таблице `Files` хранятся отображаемое имя, размер, MIME-тип и служебное имя на диске.
3. Все запросы к файлам и папкам фильтруются по `OwnerId` — чужой объект вернёт `404`.
4. Удаление — мягкое (`IsDeleted` + `DeletedAt`). Файл на диске удаляется только
   при окончательном удалении из корзины.
5. Занятое место считается как сумма размеров неудалённых файлов пользователя
   и сравнивается с `Users.StorageLimitBytes`.

## Ограничения учебной версии

- SQLite выбрана для простого запуска без отдельного сервера БД; структура и EF Core
  позволяют перейти на PostgreSQL заменой провайдера.
- Пароли к общим ссылкам, срок действия ссылок и админ-панель появятся в неделях 3–4.
- Файлы хранятся на локальном диске, без S3 и фоновой обработки.
